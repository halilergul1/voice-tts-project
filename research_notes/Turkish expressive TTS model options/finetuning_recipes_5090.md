# Fine-tuning / continued-pretraining recipes for open TTS models on Turkish, single RTX 5090 (32 GB) — research notes (as of 2026-10-26)

Scope note: every claim below carries a source link. Numbers are reported as the source states them (GPU, batch, steps); where a source gives only a filename or a snippet, that is said explicitly. "Unknown" means I found no reliable source. Search/fetch coverage: official repos, HF model cards, GitHub issues, Unsloth docs, a handful of arXiv papers and community write-ups. Items marked "(search snippet)" come from a search-result summary rather than a fetched page and should be re-verified before being relied on.

---

## KQ1. Per-model recipes: training code status, data format, data size, VRAM/throughput, new-language results, gotchas

### Takeaway
Of the ~20 families, only about half have usable public training code as of Oct 2026: XTTS-v2 (idiap fork), F5-TTS, Fish-Speech (only on tags ≤ v1.5.x / pre-v3.0.0 — training tools were deliberately deleted from `main` on 2026-10-13), CosyVoice 2/3, Orpheus (plus Unsloth), Llasa, Qwen3-TTS (single-speaker SFT only), VoxCPM 1.5/2, Parler-TTS, StyleTTS2, Piper/VITS, and community-only trainers for Chatterbox, IndexTTS2 and Sesame CSM. Zonos, Kyutai TTS and Higgs Audio have no official training code and the maintainers have said (Zonos, Chatterbox) they will not release one. Models that already cover Turkish out of the box (so no tokenizer/new-language work is needed): XTTS-v2, Chatterbox-Multilingual, VoxCPM2, Piper (espeak-ng `tr`).

### Cited Findings

#### XTTS-v2 (Coqui; maintained in idiap/coqui-ai-TTS)
- Only the GPT encoder can be trained: "Current implementation only supports inference and GPT encoder training." A Gradio demo (`TTS.demos.xtts_ft_demo.xtts_demo`) does data processing (faster-whisper), GPT fine-tuning and inference; the docs say fine-tuning "can take up to 40 minutes" on Colab. Official language list on the docs page is 17 and includes Turkish — [Coqui XTTS docs](https://coqui-tts.readthedocs.io/en/latest/models/xtts.html)
- The recipe `recipes/ljspeech/xtts_v2/train_gpt_xtts.py` defaults: `BATCH_SIZE = 3`, `GRAD_ACUMM_STEPS = 84` (comment: batch × accum should be ≥ 252), `max_wav_length = 255995` samples (~11.6 s at 22050 Hz), `max_text_length = 200`, conditioning 3–6 s, input/DVAE sample rate 22050 Hz, output 24000 Hz, lr 5e-6 AdamW (betas 0.9/0.96, wd 1e-2), MultiStepLR; downloads `dvae.pth`, `mel_stats.pth`, `model.pth`, `vocab.json` from coqui/XTTS-v2 — [train_gpt_xtts.py](https://github.com/idiap/coqui-ai-TTS/blob/dev/recipes/ljspeech/xtts_v2/train_gpt_xtts.py)
- VRAM reports (default recipe): RTX 3060 12 GB OOM at batch 3 (accum 84) and batch 2 (accum 126); batch 1 (accum 252) worked. An 8 GB RTX 3070 user succeeded on Windows only with "CUDA – Sysmem Fallback" (17 GB combined VRAM+RAM). Maintainer suggested float16 — [coqui-ai/TTS discussion #3268](https://github.com/coqui-ai/TTS/discussions/3268)
- XTTS-v2 was trained on 16 languages including Turkish, GPT2 backbone, "primarily publicly available datasets"; no per-language hours given — [erogol, XTTSv2 notes](https://erogol.substack.com/p/xttsv2-notes)
- Adding Hindi to the idiap fork required only sentence-splitting and a per-language tokenizer char limit; commit notes "the XTTS model itself already supports Hindi" — [idiap/coqui-ai-TTS PR #4](https://github.com/idiap/coqui-ai-TTS/pull/4/files)
- New-language precedent (search snippet): a paper fine-tuned XTTS for Vietnamese with 100 h sampled from viVoice; an Egyptian-Arabic project fine-tuned only the GPT and kept the DVAE frozen — [arXiv 2505.16972](https://arxiv.org/pdf/2505.16972); [arXiv 2602.15675](https://arxiv.org/pdf/2602.15675)

#### F5-TTS (SWivid)
- Training README: fine-tune via `src/f5_tts/train/finetune_gradio.py` (discussion #143) or `accelerate launch src/f5_tts/train/train.py --config-name F5TTS_v1_Base.yaml`; Hydra overrides such as `++datasets.batch_size_per_gpu=19200` with `--mixed_precision=fp16`; custom data = CSV `audio_file|text` (absolute paths) → `prepare_csv_wavs.py`; early fine-tuned checkpoints "may perform worse with EMA on" (use `use_ema=False`) — [F5-TTS train README](https://github.com/SWivid/F5-TTS/blob/main/src/f5_tts/train/README.md)
- Maintainer (SWivid) in the new-language thread: full fine-tune only (no LoRA/adapters at the time); reuse the pretrained `vocab.txt` (Emilia zh/en pinyin vocab); lr ≈ 1e-4 with few warmup steps; "didn't specifically experiment with finetuning". Community runs: **Greek** 40 h Greek + 20 h LibriTTS-R English, ~half a day on one RTX 4090, 100k–150k steps, lr 1e-5, `batch_size_per_gpu 1618` (frame), `max_samples 64`, 11 epochs, 500 warmup — both languages reported working, vocab not replaced; **Spanish** (jpgallegoar) one epoch ≈ 6 h 51 min on a 4090 at batch 4000 frames over 93k batches; **Chinese** 33 h at lr 7.5e-5 — pronunciation degraded at later checkpoints (126k vs 12.6k steps); typical clip length 3–12 s; 3090 setup for 60–80 h used 10 epochs; prep script assumes pinyin tokenization and non-Latin scripts need changes; Japanese converted kanji→hiragana before training; host RAM ~20 GB idle (`num_workers` default 16) — [F5-TTS discussion #57](https://github.com/SWivid/F5-TTS/discussions/57)
- Community model list (SHARED.md): German (hvoss-techfak; Common Voice 19 + 800 h crowdsourced), Finnish (AsmoKoskinen; Common Voice + VoxPopuli), Spanish (218 h), Italian (CML-TTS), Russian/Latvian (Common Voice), Japanese (custom `vocab_japanese.txt`, Emilia 1.7k h JA + 5.4k h Galgame), Hindi, Arabic. No Turkish or Hungarian entry; all non-Japanese entries reuse `vocab.txt` — [F5-TTS SHARED.md](https://github.com/SWivid/F5-TTS/blob/main/src/f5_tts/infer/SHARED.md)
- German card: "trained for 4.2 million steps", batch 8000 frames/GPU, accum 1, lr 1.8e-5, 2000 warmup, 40 epochs, bf16, tokenizer `pinyin`; GPU/time not stated — [hvoss-techfak/F5-TTS-German](https://huggingface.co/hvoss-techfak/F5-TTS-German)
- Turkish community checkpoint exists: base SWivid/F5-TTS, dataset Common Voice 17.0, file `f5_tts_turkish_1000000.safetensors` (step count implied by filename only), ships `vocab.txt`, recommends NFE 64; hours/GPU not stated; CC-BY-NC-4.0 — [marduk-ra/F5-TTS-Turkish](https://huggingface.co/marduk-ra/F5-TTS-Turkish)
- Kurdish Sorani F5-TTS fine-tune with ~10 h single-speaker: CER 4.3 %, MOS 4.72 (search snippet) — [UHD Journal](https://journals.uhd.edu.iq/index.php/uhdjst/article/download/1609/1021/7333)
- Indian-language F5 study ablated 1 / 10 / 100 h per language (search snippet) — [arXiv 2505.20693](https://arxiv.org/html/2505.20693v1)
- Cross-Lingual F5-TTS 2 (Sep 2026): alignment-free adaptation that builds same-speaker prompt/target pairs with the pretrained model and runs "a short fine-tuning stage"; search snippet claims the smallest data scale reached performance close to the full set — [arXiv 2609.15184](https://arxiv.org/abs/2609.15184)
- Practitioner pitfall: checkpoints hold raw and EMA weights; the EMA copy is the one to warm-start from (search snippet) — [TowardsAI post](https://pub.towardsai.net/what-i-got-wrong-fine-tuning-f5-tts-for-a-new-writing-system-ce2576bddbb0)

#### Fish-Speech / OpenAudio S1-mini
- S1-mini is the open 0.5B distilled model; full S1 (4B) is cloud-only — [fish.audio "Introducing S1"](https://fish.audio/blog/introducing-s1/)
- Recipe (v1.5.1 docs, still valid in structure for S1-era code): `data/SPK1/*.wav` + `.lab` transcript per clip; loudness-normalize with `fap loudness-norm data-raw data --clean`; `tools/vqgan/extract_vq.py` (`--batch-size 16`, config `firefly_gan_vq`) → `.npy` per clip; `tools/llama/build_dataset.py` → `quantized-dataset-ft.protos`; `python fish_speech/train.py --config-name text2semantic_finetune +lora@model.model.lora_config=r_8_alpha_16`; batch/accum set in `text2semantic_finetune.yaml`; `tools/llama/merge_lora.py` required before inference; "by default, the model learns speaker speech patterns, not timbre" — pick the earliest acceptable checkpoint — [fish-speech v1.5.1 finetune.md](https://raw.githubusercontent.com/fishaudio/fish-speech/v1.5.1/docs/en/finetune.md)
- A working S2-Pro LoRA run (Oct 4 2026): `.lab` + audio → `extract_vq` (`modded_dac_vq`) → `build_dataset` → LoRA r=8, α=16, dropout 0.01 on attention/mlp/embeddings/output, lr 5e-5, 300 warmup, batch 1 × accum 4, bf16, `max_length 4096`, 11,133 train protos, on an RTX PRO 6000 Blackwell (96 GB) with PyTorch 2.8.0+cu128; free generation became unstable (near-silent output) after 1000 steps even though teacher-forced CE improved; no maintainer reply — [fish-speech issue #1346](https://github.com/fishaudio/fish-speech/issues/1346)
- PR #1350 "Update for Drama-3" (merged 2026-10-13, version bumped to 3.0.0) states "this branch removes the training/data-prep tools on purpose" and drops lightning/loralib/tensorboard/wandb from `uv.lock`; Drama 3 needs 48 GB in FP8 — [fish-speech PR #1350](https://github.com/fishaudio/fish-speech/pull/1350). Consistent with this, `docs/en/finetune.md` on `main` and `docs.fish.audio/.../fine-tuning` returned 404 when fetched on 2026-10-26.
- Community: LoRA scheduled-sampling discussion for stable no-prompt character voices — [fish-speech discussion #1314](https://github.com/fishaudio/fish-speech/discussions/1314)

#### CosyVoice 2 / Fun-CosyVoice 3
- README: Fun-CosyVoice 3.0 covers 9 languages (zh, en, ja, ko, de, es, fr, it, ru) + 18 Chinese dialects; roadmap 2025/12: release Fun-CosyVoice3-0.5B-2512 base, RL model "and its training/inference script"; training scripts live in `examples/libritts` "for advanced users" — [FunAudioLLM/CosyVoice](https://github.com/FunAudioLLM/CosyVoice)
- `examples/libritts/cosyvoice2/run.sh`: stages = Kaldi files (wav.scp/text/utt2spk) → campplus speaker embeddings → `speech_tokenizer_v3.onnx` speech tokens → parquet (1000 utts/file) → `torchrun` on `CUDA_VISIBLE_DEVICES="0,1,2,3"` training `llm`, `flow`, `hifigan` from the pretrained `.pt` (echo says "We only support llm traning for now"), `train_engine=torch_ddp` (DeepSpeed optional, `conf/ds_stage2.json`) → average last 5 checkpoints → export JIT/ONNX — [cosyvoice2 run.sh](https://github.com/FunAudioLLM/CosyVoice/blob/main/examples/libritts/cosyvoice2/run.sh)
- `conf/cosyvoice2.yaml`: 24 kHz audio, 80-mel/hop 480; speech tokens 25 Hz, vocab 6561; `token_max_length 200`; dynamic batching `max_frames_in_batch 2000`; LLM stage Adam lr 1e-5 (commented as the SFT value), constant LR, 2500 warmup, `accum_grad 2`, max 200 epochs; GAN stage lr 2e-4; text tokenizer `get_qwen_tokenizer` (user supplies the Qwen2 tokenizer path); `use_spk_embedding` must be set True for SFT — [cosyvoice2.yaml](https://github.com/FunAudioLLM/CosyVoice/blob/main/examples/libritts/cosyvoice2/conf/cosyvoice2.yaml)
- CosyVoice 2 training data: 130k h zh, 30k h en, 4.6k h ja, 2.2k h ko; the speech tokenizer (trained on zh/en only) "showed zero-shot capability for other languages" (search snippet) — [arXiv 2412.10117](https://arxiv.org/pdf/2412.10117)
- New-language fine-tunes: **Uzbek "Navoiy TTS"** on CosyVoice2-0.5B, ~600 h neutral + ~40 h expressive/emotional speech (search snippet; the card itself only shows the checkpoint `emotion_600h_joint.pt`) — [aisha-org/navoiy-tts](https://huggingface.co/aisha-org/navoiy-tts). **Tajik/Uzbek/Kazakh** on CosyVoice3-0.5B with ~1.78 M utterances (642k/645k/500k), round-trip WER 17.6/16.7/12.5 % on FLEURS; language inferred from script; modules/GPU/time not stated — [Tohirju/cosyvoice3-central-asian](https://huggingface.co/Tohirju/cosyvoice3-central-asian)
- Alibaba also offers paid CosyVoice fine-tuning via API (not local) — [Aliyun Model Studio](https://help.aliyun.com/en/model-studio/fine-tune-speech-synthesis-model-by-api)

#### Orpheus-TTS (Canopy Labs; Llama-3.2-3B + SNAC 24 kHz)
- README: base pretrained on "100k+ hours of English speech"; 3B trained on 8192-token packed sequences; finetune = HF dataset in `zac-sample-dataset` format, preprocessing notebook (<1 min per 1000 rows), `finetune/config.yaml`, `accelerate launch train.py`, LoRA permitted; "start to see high quality results after ~50 examples", ~300 examples/speaker for best results; for a new language/style the author recommends finetuning without a text dataset, noting most forgetting of semantic ability happens early ("<100000 rows"); multilingual research preview with 7 pretrain/finetune pairs — [canopyai/Orpheus-TTS](https://github.com/canopyai/Orpheus-TTS)
- Multilingual collection (updated Apr 2025): zh, hi, ko, fr, de, es_it, each with `*-pretrain-research_release` and `*-ft-research_release`; no Turkish; no training guide found — [canopylabs multilingual collection](https://huggingface.co/collections/canopylabs/orpheus-multilingual-research-release)
- Unsloth TTS guide: notebooks for Sesame-CSM-1B, Orpheus-3B, Spark-0.5B, Llasa-1B, Oute-1B, Whisper; resample to 24 kHz for Orpheus; dataset = `audio` + `text`, emotion tags like `<laugh>`, `<sigh>`; example Elise ≈ 3 h / 1.2k samples; defaults LoRA 16-bit, lr 2e-4, batch 1 × accum 4, `max_seq_length 2048`; "a few epochs" on ~3 h ≈ 1–2 h on a Colab T4; full fine-tune via `full_finetuning=True`; claims 1.5× faster / 50 % less memory; no explicit VRAM table; "support new languages" listed as a goal without a procedure — [Unsloth TTS fine-tuning docs](https://unsloth.ai/docs/basics/text-to-speech-tts-fine-tuning)
- **Turkish Orpheus v2**: base `unsloth/orpheus-3b-0.1-pretrained`, 20,000 samples of `afkfatih/turkish-tts-combined-raw` (~81k available; hours not stated), LoRA r=32 α=64 on all projections (~185 M trainable), lr 2e-5, 8 epochs = 9,504 steps, batch 2 × accum 4 (eff. 16), seq 4096, bf16 + FlashAttention-2, on A100 80 GB (card inconsistent: 2×A100 vs 2 nodes × 1); eval loss 9.50 → 4.35; Whisper-small proxy WER 1.576 → 0.723, CER 1.224 → 0.410 (author calls it a proof of concept with noisy metrics); SNAC `hubertsiuzdak/snac_24khz`, 7 tokens/frame, only audio tokens in the loss — [AbDhumal/orpheus-3b-turkish-tts-v2](https://huggingface.co/AbDhumal/orpheus-3b-turkish-tts-v2)
- Kazakh continued pretraining with a 70/30 Kazakh/English mix: "after training, the model forgets the emotion tokens, and it doesn't recognize the original speaker tokens anymore" (search snippet; thread not fetchable) — [r/unsloth thread](https://redlib.ssps.io/r/unsloth/comments/1l8nyps/finetuning_unslothorpheus3b)
- Sunbird fine-tuned `unsloth/orpheus-3b-0.1-pretrained` on 20 language configurations; quality "varies by language" with corpus hours — [Sunbird Orpheus-3B](https://salt.sunbird.ai/models/orpheus-3b-tts-multilingual/)

#### Chatterbox / Chatterbox-Multilingual (Resemble)
- Official stance (May 30 2025): "we're not releasing the training code" — fine-tuning is sold via the Resemble API. Community repos named in the thread: stlohrey/chatterbox-finetuning (T3 script "working", German WIP), alisson-anjos/chatterbox-finetune; a commenter replaced unused vocab entries with missing letters for other EU languages — [resemble-ai/chatterbox issue #32](https://github.com/resemble-ai/chatterbox/issues/32); later issues #139, #239, #373 ("how to add a new language", Dec 2025) remain community-only — [issue list](https://github.com/resemble-ai/chatterbox/issues?q=training+code)
- Chatterbox-Multilingual supports 23 languages including Turkish; dedicated single-language fine-tunes exist for zh, es, pt, hi but not Turkish (search snippet) — [ResembleAI/chatterbox README](https://huggingface.co/ResembleAI/chatterbox/blob/main/README.md)
- **Uzbek fine-tune** of Multilingual v3 (`t3_mtl23ls_v2`, 2454-token vocab): T3 only (s3gen + voice encoder frozen), 100k utts ≈ 119.4 h, lr 1e-5, fp32, 12,500 steps, shipped step 6,000 chosen by WER sweep; reused the Turkish `tr` language token because it "fits Uzbek Latin best"; FLEURS-uz round-trip WER 19.1 % mean / 14.8 % median — [Tohirju/chatterbox-mtl-uzbek](https://huggingface.co/Tohirju/chatterbox-mtl-uzbek)
- **Finnish fine-tune**: 16,604 samples (Common Voice 15, Filmot, YouTube, Parliament), A100 80 GB bf16, reported checkpoint step 986, zero-shot OOD WER 28.94 % → 2.76 %, LLM-rated MOS 2.29 → 4.34; built on the gokhaneraslan toolkit — [RASMUS/Chatterbox-Finnish](https://huggingface.co/RASMUS/Chatterbox-Finnish)
- gokhaneraslan/chatterbox-finetuning: full FT or LoRA (defaults r=64, α=128 on `c_attn,c_proj,c_fc,spkr_enc`, saves `text_emb`/`text_head`), vocabulary resizing with mean-initialised new tokens (Turbo BPE extended to 52,260), mandatory offline preprocessing (voice-encoder embeddings, S3Gen tokens), Silero VAD; input 16/22.05/44.1 kHz resampled to 16 kHz, output 24 kHz; "3–10 s per segment, at least 30 minutes total"; LoRA ≈ 60 % less VRAM, recommended for ≤ 10 h; default tokenizer already covers Turkish (ç ğ ş ö ü ı) and the README inference example is Turkish — [gokhaneraslan/chatterbox-finetuning](https://github.com/gokhaneraslan/chatterbox-finetuning)
- stlohrey/chatterbox-finetuning: `src/finetune_t3.py`, example on `MrDragonFox/DE_Emilia_Yodas_680h`, lr 5e-5, 100 warmup, batch 4 × accum 2, fp16, 1 epoch; no VRAM/time stated — [stlohrey/chatterbox-finetuning](https://github.com/stlohrey/chatterbox-finetuning)

#### Llasa (HKUST; Llama + X-codec2)
- Training repo: `torchrun --nproc_per_node=8 train_tts.py config.json`; text via Llama tokenizer, speech via X-codec2 with IDs offset into one vocabulary; ~160k h tokenized open data released (LibriHeavy, Emilia zh/en, WenetSpeech4TTS) of ~250k h total; DeepSpeed ZeRO-2/3 configs; 1B multilingual checkpoint announced 2025-02-07 — [zhenye234/LLaSA_training](https://github.com/zhenye234/LLaSA_training)
- `finetune/`: online (codec runs during training, more VRAM) vs offline (pre-encode); `offline_finetune/` has `finetune_offline_lora.py` + `config_lora.json`, `ds_config_zero2.json`, examples use `--nproc_per_node=4`, single-speaker LJSpeech example — [finetune README](https://github.com/zhenye234/LLaSA_training/tree/main/finetune); [offline_finetune](https://github.com/zhenye234/LLaSA_training/tree/main/finetune/offline_finetune)
- X-codec2 handles 16 kHz only; `xcodec2==0.1.5` recommended for Llasa fine-tuning (search snippet) — [HKUSTAudio/Llasa-3B](https://huggingface.co/HKUSTAudio/Llasa-3B); [X-codec repo](https://github.com/jinluo12345/Xcodec)
- **German**: on `HKUSTAudio/Llasa-1B-Multilingual`, 7,000 h custom corpus, 4× L40S, ~20 h raw training (excluding xcodec2 preprocessing), restarted after 3 crashes; existing xcodec2 reused; "audio glitches can happen" with a reference speaker — [MultiLlasa/Llasa-1B-Multilingual-German](https://huggingface.co/MultiLlasa/Llasa-1B-Multilingual-German)

#### IndexTTS 2 (Bilibili)
- Official repo lists IndexTTS-2 release 2025/09/08; no training code found in README — [index-tts/index-tts](https://github.com/index-tts/index-tts)
- Unofficial trainer (issue #501, opened 2025-10-20, ~50 comments): JarodMica `training_v2` branch — trains the GPT only (s2mel untouched), `train_bpe.py` + `train_gpt_v2.py`, "no instructions"; Japanese: BPE appended to 24k tokens, ~1,100 h Emilia-Yodas ≈ 1.5 + 4 epochs; multilingual experiment ~1,000 h each de/fr/en/ko/ja + 300 h zh, ~30k steps, tokenizer 50k; hardware reports: single RTX 6000 Pro at batch 16–32, or 4 GPUs at batch 64/GPU; advice: not LoRA so forgetting occurs, include base languages, compare by ear not loss; accent leakage in multilingual runs; Malay worked with the original tokenizer (Latin script); output ≈ 22 kHz — [index-tts issue #501](https://github.com/index-tts/index-tts/issues/501)

#### Qwen3-TTS (Alibaba; 12 Hz codec)
- Official `finetuning/`: "currently supports single-speaker fine-tuning" for `Qwen3-TTS-12Hz-1.7B-Base` / `0.6B-Base`; JSONL lines `{audio, text, ref_audio}`; `prepare_data.py` (extracts `audio_codes` with `Qwen/Qwen3-TTS-Tokenizer-12Hz`) → `sft_12hz.py --batch_size --lr --num_epochs --speaker_name`; examples conflict (batch 32 / lr 2e-6 / 10 epochs vs batch 2 / lr 2e-5 / 3 epochs); same `ref_audio` for all samples recommended; multi-speaker "in future releases"; no LoRA, VRAM or language notes — [Qwen3-TTS finetuning README](https://github.com/QwenLM/Qwen3-TTS/blob/main/finetuning/README.md)
- Supported languages: zh, en, ja, ko, de, fr, ru, pt, es, it — **Turkish not included**; tokenizer 12.5 fps, 16 quantizers, codebook 2048; 2B params in bf16 — [Qwen/Qwen3-TTS-12Hz-1.7B-Base](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-Base); tech report [arXiv 2601.15621](https://arxiv.org/pdf/2601.15621)
- New-language precedent (Emirati Arabic, not in the supported list): full FT of 1.7B, speaker encoder frozen, lr 2e-6 AdamW wd 0.01, effective batch ~32, 10 epochs, bf16; new language embedding warm-started from the mean of existing language embeddings; Arabic auto-detected by Unicode range; hours/GPU/time not stated — [vadimbelsky/qwen3.5-TTS-Emirati](https://huggingface.co/vadimbelsky/qwen3.5-TTS-Emirati)
- Community wrapper: "~16 GB VRAM recommended", 10–100 samples "work well" for single speaker, 5–30 s clips, defaults batch 2 / lr 2e-5 / 3 epochs — [sruckh/Qwen3-TTS-finetune](https://github.com/sruckh/Qwen3-TTS-finetune)
- Baseten: 800 clips (~1.5 h LJSpeech), one H100, ~1 h for 8 epochs, lr ≤ 1e-5 with warmup + cosine; on 1.5 h fine-tuning did not clearly beat zero-shot cloning on similarity/MOS — [Baseten blog](https://www.baseten.co/blog/fine-tuning-qwen3-tts-for-high-quality-voice-cloning/)

#### VoxCPM 1.5 / VoxCPM2 (OpenBMB; tokenizer-free, LM + flow-matching)
- Fine-tune guide: `scripts/train_voxcpm_finetune.py --config_path …` (LoRA via a `lora:` key); JSONL `{audio, text, ref_audio?, duration?, dataset_id?}`; `sample_rate` must be 16 kHz for VoxCPM2 (44.1 kHz for 1.5); clips 3–30 s, <1 s unstable; trailing silence < 0.5 s; 30–50 % of samples with `ref_audio`; rough VRAM at batch 16 / `max_batch_tokens 8192`: VoxCPM 1.5 (750M) LoRA ~12 GB / full ~24 GB; VoxCPM2 (2B) LoRA ~20 GB / full ~40 GB; LoRA lr 1e-4 (r=32 cloning, 64 for style/language), full lr 1e-5; example configs run 1000 steps; 1–3 epochs for single speaker — [VoxCPM fine-tuning guide](https://voxcpm.readthedocs.io/en/latest/finetuning/finetune.html)
- FAQ: for a new language "full fine-tuning with 500+ hours of target-language data", mix in zh/en to reduce forgetting, lr 1e-5; LoRA ≈ half the VRAM; DDP adds ~10 GB/card; overfitting (ignoring text) "within a few hundred steps on small datasets"; keep `training_cfg_rate=0.1` — [VoxCPM FAQ](https://voxcpm.readthedocs.io/en/latest/finetuning/faq.html)
- VoxCPM2 lists 30 languages including **Turkish** (search snippet from README/docs) — [VoxCPM README mirror](https://github.com/justdn/VoxCPM); [VoxCPM2 docs](https://voxcpm.readthedocs.io/en/latest/models/voxcpm2.html)
- Khmer/Korean LoRA study (Jun 2026): one shared zero-init LoRA on LM + decoder, 25.5 h total cleaned data; rank 64 best for Khmer (MOS 3.85 → 4.23, p<0.001), Korean no significant gain; 0.19–3.03 % trainable params; GPU/time not in abstract — [arXiv 2606.26618](https://arxiv.org/abs/2606.26618)

### Inferences

Zonos/Kyutai/Higgs are inference-only.

## KQ2. Which models are realistic for Turkish on one 32 GB RTX 5090 within days, and which need clusters?

### Takeaway
Documented VRAM figures put LoRA/SFT of 0.5–3B LLM-codec models, F5-TTS full fine-tune, XTTS GPT fine-tune, VoxCPM LoRA, Chatterbox T3, Piper and StyleTTS2 within 32 GB; the cluster-scale cases are *new-language pretraining* at the data volumes maintainers recommend (VoxCPM 500+ h full FT, IndexTTS2 ~1,000 h/language, Llasa-German 7,000 h on 4× L40S, Parler-multilingual 9,200 h) rather than the models per se.

### Cited Findings
- XTTS GPT fine-tune runs at batch 1 on 12 GB (OOM at batch 2–3 with the default ~11.6 s clips) — [coqui discussion #3268](https://github.com/coqui-ai/TTS/discussions/3268); recipe defaults batch 3 × accum 84 — [train_gpt_xtts.py](https://github.com/idiap/coqui-ai-TTS/blob/dev/recipes/ljspeech/xtts_v2/train_gpt_xtts.py)
- F5-TTS full fine-tune on a 24 GB RTX 4090 at 1,618–4,000 frames per batch (Greek 60 h ≈ half a day; Spanish 1 epoch ≈ 6 h 51 min) — [F5-TTS discussion #57](https://github.com/SWivid/F5-TTS/discussions/57)
- VoxCPM2 (2B) LoRA ≈ 20 GB, full ≈ 40 GB at batch 16 / 8192 tokens; VoxCPM 1.5 full ≈ 24 GB — [VoxCPM guide](https://voxcpm.readthedocs.io/en/latest/finetuning/finetune.html)
- Qwen3-TTS 1.7B single-speaker SFT: "~16 GB VRAM recommended" (community wrapper) — [sruckh/Qwen3-TTS-finetune](https://github.com/sruckh/Qwen3-TTS-finetune); 1 h on one H100 for 1.5 h of data × 8 epochs — [Baseten](https://www.baseten.co/blog/fine-tuning-qwen3-tts-for-high-quality-voice-cloning/)
- Orpheus-3B Turkish LoRA used A100 80 GB at batch 2 × accum 4, seq 4096 (VRAM not stated) — [AbDhumal card](https://huggingface.co/AbDhumal/orpheus-3b-turkish-tts-v2); Unsloth's Orpheus notebook runs on a Colab T4 (16 GB) — [Unsloth docs](https://unsloth.ai/docs/basics/text-to-speech-tts-fine-tuning)
- Chatterbox T3 LoRA ≈ 60 % less VRAM than full FT; gradient checkpointing on by default — [gokhaneraslan toolkit](https://github.com/gokhaneraslan/chatterbox-finetuning); Finnish run used a single A100 80 GB — [RASMUS/Chatterbox-Finnish](https://huggingface.co/RASMUS/Chatterbox-Finnish)
- Fish S2-Pro LoRA ran at batch 1 × accum 4, seq 4096 on a 96 GB card (actual usage not stated) — [fish-speech #1346](https://github.com/fishaudio/fish-speech/issues/1346)
- Piper: trained on 24–48 GB cards, success reported with 8 GB — [piper TRAINING.md](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/TRAINING.md)
- Multi-GPU-scale precedents: Llasa German 7,000 h / 4× L40S / 20 h — [MultiLlasa card](https://huggingface.co/MultiLlasa/Llasa-1B-Multilingual-German); IndexTTS2 unofficial ~1,000–1,100 h per language on an RTX 6000 Pro (96 GB) or 4 GPUs — [index-tts #501](https://github.com/index-tts/index-tts/issues/501); Parler Mini 45k h on 32× H100 for 1.5 days — [parler README](https://github.com/huggingface/parler-tts/blob/main/training/README.md); CosyVoice2 run.sh assumes 4 GPUs — [run.sh](https://github.com/FunAudioLLM/CosyVoice/blob/main/examples/libritts/cosyvoice2/run.sh); StyleTTS2 1 h fine-tune on 4× A100 ≈ 4 h — [StyleTTS2](https://github.com/yl4579/StyleTTS2)
- VoxCPM maintainers: new language ⇒ 500+ h full FT — [VoxCPM FAQ](https://voxcpm.readthedocs.io/en/latest/finetuning/faq.html)

### Inferences
- Feasible on one 5090 (32 GB) with documented recipes: XTTS-v2 GPT (Turkish already supported), F5-TTS full FT (24 GB precedent), VoxCPM2 LoRA (~20 GB) / VoxCPM 1.5 full (~24 GB), Qwen3-TTS 0.6B/1.7B SFT (~16 GB), Orpheus-3B LoRA (Unsloth/T4-class), Llasa-1B LoRA/full (1B; the 4-GPU example is for throughput, not memory — inference), Chatterbox T3 LoRA (Turkish supported), CosyVoice2-0.5B LLM SFT (0.5B — inference from size; no single-GPU VRAM figure found), Fish S1-mini LoRA on a pinned tag (0.5B — inference), Piper/VITS, StyleTTS2 with reduced `max_len`/batch.
- Cluster- or week-scale: anything that follows the maintainers' *new-language* data recommendations (≥500–1,000 h) — VoxCPM2 full FT (needs ~40 GB at the default batch anyway), IndexTTS2 GPT retrain, Llasa continued pretraining at thousands of hours, Parler multilingual.
- Not trainable at all today: Zonos, Kyutai TTS, Higgs Audio (official), Chatterbox (official), CSM (official).

### Gaps
- No measured VRAM for Orpheus-3B LoRA at seq 4096, CosyVoice2 LLM SFT, Fish S1-mini LoRA, StyleTTS2 or Chatterbox T3 on a single 24–32 GB card; the figures above are precedents on larger GPUs.
- No RTX 5090 training throughput numbers for any TTS model were found; all timings are 4090/A100/H100/L40S.

## KQ3. LLM-over-codec models (Orpheus, Llasa, Fish, CosyVoice, Higgs, Qwen3-TTS, Chatterbox, IndexTTS2): recipe for adding a language, reported N hours, and whether the codec handles Turkish without retraining

### Takeaway
Every public new-language report reuses the frozen codec/tokenizer (SNAC, X-codec2, Fish VQ, CosyVoice FSQ tokenizer, Qwen3 12 Hz tokenizer, Chatterbox S3Gen, IndexTTS2 s2mel) and trains only the text→token LM; the text side either already covers Turkish (Chatterbox grapheme vocab, Llama/Qwen BPE) or is extended with mean-initialised tokens/embeddings. Reported data for a *credible* new language ranges from ~120 h (Chatterbox-Uzbek, T3 only) and ~20k samples (Orpheus-Turkish LoRA, "proof of concept") up to 600 h (CosyVoice2-Uzbek), ~1,000 h (IndexTTS2-Japanese) and 7,000 h (Llasa-German); catastrophic forgetting of English/emotion/speaker tokens is reported repeatedly.

### Cited Findings
- Orpheus README: for a new language, fine-tune (no text corpus), because semantic forgetting happens early ("<100000 rows"); synthetic data discouraged for pretraining (low codebook utilisation) — [canopyai/Orpheus-TTS](https://github.com/canopyai/Orpheus-TTS). Turkish LoRA on 20k samples reused `snac_24khz` unchanged; only audio tokens in the loss — [AbDhumal card](https://huggingface.co/AbDhumal/orpheus-3b-turkish-tts-v2). Kazakh 70/30 continued pretraining lost emotion and speaker tokens (search snippet) — [r/unsloth](https://redlib.ssps.io/r/unsloth/comments/1l8nyps/finetuning_unslothorpheus3b)
- Llasa: German used the existing `HKUST-Audio/xcodec2` (16 kHz) with 7,000 h, 4× L40S, 20 h — [MultiLlasa card](https://huggingface.co/MultiLlasa/Llasa-1B-Multilingual-German); text tokenizer is the Llama tokenizer, speech IDs offset after text vocab + 8 specials — [LLaSA_training](https://github.com/zhenye234/LLaSA_training)
- CosyVoice: tokenizer trained on zh/en "showed zero-shot capability for other languages" (search snippet) — [arXiv 2412.10117](https://arxiv.org/pdf/2412.10117); Uzbek on CosyVoice2 with ~600 h + 40 h expressive (search snippet) — [navoiy-tts](https://huggingface.co/aisha-org/navoiy-tts); Tajik/Uzbek/Kazakh on CosyVoice3 with ~1.78 M utterances, language inferred from script — [cosyvoice3-central-asian](https://huggingface.co/Tohirju/cosyvoice3-central-asian); text tokenizer is Qwen2 BPE (`get_qwen_tokenizer`) — [cosyvoice2.yaml](https://github.com/FunAudioLLM/CosyVoice/blob/main/examples/libritts/cosyvoice2/conf/cosyvoice2.yaml)
- Qwen3-TTS Emirati Arabic (unsupported language): full FT, new language embedding = mean of existing language embeddings, codec untouched — [Emirati card](https://huggingface.co/vadimbelsky/qwen3.5-TTS-Emirati)
- Chatterbox: Uzbek trained T3 only with s3gen/voice-encoder frozen, 119.4 h, reused the `tr` token — [Uzbek card](https://huggingface.co/Tohirju/chatterbox-mtl-uzbek); Finnish 16.6k samples, WER 28.9 → 2.8 % — [Finnish card](https://huggingface.co/RASMUS/Chatterbox-Finnish); vocab resizing with mean-init new tokens — [gokhaneraslan toolkit](https://github.com/gokhaneraslan/chatterbox-finetuning); community note that the S3 block "may also need fine-tuning to remove an accent" — [chatterbox #32](https://github.com/resemble-ai/chatterbox/issues/32)
- IndexTTS2 unofficial: GPT only, s2mel untouched; Japanese BPE appended (24k), ~1,100 h; "include the base languages in training, or they degrade"; multilingual runs show accent leakage — [index-tts #501](https://github.com/index-tts/index-tts/issues/501)
- Fish-Speech: VQ tokens extracted with the shipped codec (`firefly_gan_vq` / `modded_dac_vq`), LoRA r=8 α=16 on the LLM — [v1.5.1 finetune.md](https://raw.githubusercontent.com/fishaudio/fish-speech/v1.5.1/docs/en/finetune.md); [#1346](https://github.com/fishaudio/fish-speech/issues/1346)
- Higgs: a community fork exists to *retrain* the Higgs codec (not backward compatible) — [Respair/Higgs_Codec_Extended](https://huggingface.co/Respair/Higgs_Codec_Extended/commit/58828def0710d4bde972b532b1d02ee0b13ccc09)
- Parler multilingual kept 580 h English alongside 9,200 h non-English "to retain English capabilities" (search snippet) — [ylacombe/p-m-e](https://huggingface.co/ylacombe/p-m-e); VoxCPM FAQ likewise says mix zh/en — [VoxCPM FAQ](https://voxcpm.readthedocs.io/en/latest/finetuning/faq.html)

### Inferences
- The practical recipe for Turkish on an LLM-codec model is: (1) keep the codec frozen (every precedent did), (2) check the text tokenizer covers ç/ğ/ı/ö/ş/ü (true for Llama/Qwen BPE and Chatterbox graphemes; verify for Fish and IndexTTS2 BPE), (3) if the model has language tokens/embeddings, initialise the new one from the mean (Qwen3 precedent) or reuse `tr` (Chatterbox already has it), (4) LoRA for ≤ ~20 h, full FT with 10–30 % replay of a base language beyond that, (5) stop by listening — several threads say loss keeps falling while quality degrades.
- No source retrained SNAC, X-codec2, DAC or the CosyVoice tokenizer for a new language; the Turkish-specific risk is therefore on the text/LM side, not the codec.

### Gaps
- No controlled study reports hours-vs-WER curves for an LLM-codec model on Turkish; the Orpheus-Turkish card gives no hours and uses a Whisper-small proxy.
- Whether Fish S1-mini's text tokenizer needs extension for Turkish diacritics is unverified.

## KQ4. Flow-matching models (F5-TTS, CosyVoice flow decoder, Zonos, VoxCPM): Turkish text tokenization and community new-language results

### Takeaway
F5-TTS tokenizes raw characters (the "pinyin" vocab is a character list that already contains Latin letters, so Greek/German/Finnish/Spanish/Turkish fine-tunes reused `vocab.txt`), VoxCPM is tokenizer-free on text via its MiniCPM backbone and already lists Turkish, CosyVoice's flow decoder consumes speech tokens (language-agnostic) while the text side is Qwen BPE; Zonos cannot be trained. Community F5 new-language runs used 33–800 h, 100k–4.2M steps, and reported working output but no formal metrics except a 10 h Kurdish run (CER 4.3 %).

### Cited Findings
- F5-TTS tokenizer: maintainer says reuse the Emilia zh/en pinyin `vocab.txt`; Greek run relied on "the existing symbols supporting Greek"; prep script assumes pinyin and non-Latin scripts need changes; Japanese used a custom vocab — [#57](https://github.com/SWivid/F5-TTS/discussions/57); [SHARED.md](https://github.com/SWivid/F5-TTS/blob/main/src/f5_tts/infer/SHARED.md); German card lists `tokenizer: pinyin` — [F5-TTS-German](https://huggingface.co/hvoss-techfak/F5-TTS-German); Turkish community model ships a `vocab.txt` — [F5-TTS-Turkish](https://huggingface.co/marduk-ra/F5-TTS-Turkish)
- F5 data/steps reported: Greek 40 h (+20 h EN) 100k–150k steps; Chinese 33 h; Spanish 218 h; German CV19 + 800 h, 4.2 M steps; Kurdish 10 h CER 4.3 %/MOS 4.72; Indian languages 1/10/100 h ablation — sources as in KQ1
- F5 batch is frame-based (`batch_size_per_gpu` 1,618–19,200 frames); EMA caveat for early checkpoints — [train README](https://github.com/SWivid/F5-TTS/blob/main/src/f5_tts/train/README.md)
- VoxCPM2: 2.4B tokenizer-free model, MiniCPM-4 backbone + flow-matching decoder; 25.5 h Khmer+Korean LoRA (rank 64) improved Khmer MOS 3.85 → 4.23 — [arXiv 2606.26618](https://arxiv.org/abs/2606.26618); Turkish among 30 supported languages — [VoxCPM2 docs](https://voxcpm.readthedocs.io/en/latest/models/voxcpm2.html)
- CosyVoice2 flow: `training_cfg_rate 0.2`, trained from `flow.pt` in the same run.sh loop as the LLM; text via Qwen tokenizer — [cosyvoice2.yaml](https://github.com/FunAudioLLM/CosyVoice/blob/main/examples/libritts/cosyvoice2/conf/cosyvoice2.yaml); [run.sh](https://github.com/FunAudioLLM/CosyVoice/blob/main/examples/libritts/cosyvoice2/run.sh)
- Zonos: no training code (see KQ1) — [Zonos #2](https://github.com/Zyphra/Zonos/issues/2)
- Low-resource TTS fine-tuning study (not F5): 30 min / 1 h / 5 h subsets, 5× upsampling of new languages, lr 1e-5 for ≤ 30k steps (search snippet) — [Align2Speak, arXiv 2509.21718](https://arxiv.org/pdf/2509.21718)

### Inferences
- For Turkish on F5-TTS no vocab change should be needed (Latin script with diacritics; the German/Finnish/Spanish precedents reused `vocab.txt`), but confirm that ç ğ ı ö ş ü and İ are present in the shipped `vocab.txt` before training; the Turkish community model shipping its own `vocab.txt` suggests either it was unchanged or extended — unverified.
- F5's character tokenization means no G2P for Turkish; Turkish orthography is close to phonemic, which likely helps character models (inference, no source).

### Gaps
- No F5-TTS Turkish run reports hours, steps on a stated GPU, or WER.
- No source states F5-TTS's training sample rate on the fetched pages (the model is 24 kHz per its paper, not verified here).

## KQ5. Does 18–100 h of multi-speaker Turkish TV speech (24 kHz, 1–15 s clips, subtitles, clustered speaker IDs, background music) fit, and what preprocessing do the recipes want?

### Takeaway
18–100 h is at or above every *voice/style* fine-tune precedent (3 h Elise, 10 h Kurdish, 33–60 h F5 runs, 119 h Chatterbox-Uzbek) but below maintainers' *new-language* recommendations (VoxCPM 500+ h; IndexTTS2 ~1,000 h); clip lengths of 1–15 s exceed XTTS's 11.6 s and CosyVoice2's 200-token (~8 s) caps and VoxCPM's 3 s minimum, so per-model trimming is required; background music must be removed (Emilia-Pipe's UVR step raised DNSMOS from 2.52 to 2.88) and Fish/VoxCPM ask for loudness normalisation and < 0.5 s trailing silence.

### Cited Findings
- Clip/length limits: XTTS `max_wav_length` ≈ 11.6 s @ 22.05 kHz, text ≤ 200 chars, conditioning 3–6 s — [train_gpt_xtts.py](https://github.com/idiap/coqui-ai-TTS/blob/dev/recipes/ljspeech/xtts_v2/train_gpt_xtts.py); F5 typical 3–12 s — [#57](https://github.com/SWivid/F5-TTS/discussions/57); VoxCPM 3–30 s, < 1 s unstable, trailing silence < 0.5 s, 16 kHz for VoxCPM2 — [VoxCPM guide](https://voxcpm.readthedocs.io/en/latest/finetuning/finetune.html); CosyVoice2 `token_max_length 200` at 25 Hz tokens — [cosyvoice2.yaml](https://github.com/FunAudioLLM/CosyVoice/blob/main/examples/libritts/cosyvoice2/conf/cosyvoice2.yaml); Chatterbox toolkit 3–10 s, ≥ 30 min, resampled to 16 kHz — [gokhaneraslan](https://github.com/gokhaneraslan/chatterbox-finetuning); Qwen3-TTS wrapper 5–30 s — [sruckh](https://github.com/sruckh/Qwen3-TTS-finetune); Orpheus 24 kHz, Unsloth `max_seq_length 2048` (~10 s output at default 125 tokens) — [Unsloth](https://unsloth.ai/docs/basics/text-to-speech-tts-fine-tuning); Llasa 16 kHz — [Llasa-3B](https://huggingface.co/HKUSTAudio/Llasa-3B); Fish S2-Pro run `max_length 4096` — [#1346](https://github.com/fishaudio/fish-speech/issues/1346); StyleTTS2 24 kHz, `max_len` in 12.5 ms frames — [StyleTTS2](https://github.com/yl4579/StyleTTS2); Piper 22.05 kHz — [piper TRAINING.md](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/TRAINING.md)
- Data-size precedents: ~3 h Elise with emotion tags (Orpheus/Unsloth) — [Unsloth](https://unsloth.ai/docs/basics/text-to-speech-tts-fine-tuning); 10 h Kurdish F5 — [UHD](https://journals.uhd.edu.iq/index.php/uhdjst/article/download/1609/1021/7333); 33–60 h F5 Chinese/Greek — [#57](https://github.com/SWivid/F5-TTS/discussions/57); 25.5 h VoxCPM2 LoRA Khmer/Korean — [arXiv 2606.26618](https://arxiv.org/abs/2606.26618); 119 h Chatterbox-Uzbek — [Uzbek card](https://huggingface.co/Tohirju/chatterbox-mtl-uzbek); 600 h + 40 h expressive CosyVoice2-Uzbek — [navoiy-tts](https://huggingface.co/aisha-org/navoiy-tts); 500+ h VoxCPM new language — [FAQ](https://voxcpm.readthedocs.io/en/latest/finetuning/faq.html); ~1,000 h IndexTTS2 — [#501](https://github.com/index-tts/index-tts/issues/501)
- Multi-speaker/emotion handling: Qwen3-TTS official SFT is single-speaker only — [Qwen3-TTS finetuning](https://github.com/QwenLM/Qwen3-TTS/blob/main/finetuning/README.md); Fish learns "speech patterns, not timbre" by default (prompt for timbre) — [v1.5.1 doc](https://raw.githubusercontent.com/fishaudio/fish-speech/v1.5.1/docs/en/finetune.md); Fish Drama 3 adds speaker tags 0–15 — [PR #1350](https://github.com/fishaudio/fish-speech/pull/1350); Orpheus uses `<laugh>`, `<sigh>` etc. and Orpheus-ft was trained on 8 voice actors — [Unsloth](https://unsloth.ai/docs/basics/text-to-speech-tts-fine-tuning); StyleTTS2 and Piper take a speaker column — [StyleTTS2](https://github.com/yl4579/StyleTTS2), [piper](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/TRAINING.md); CosyVoice uses utt2spk + campplus embeddings — [run.sh](https://github.com/FunAudioLLM/CosyVoice/blob/main/examples/libritts/cosyvoice2/run.sh); VoxCPM uses `ref_audio` per sample (30–50 %) and `dataset_id` — [guide](https://voxcpm.readthedocs.io/en/latest/finetuning/finetune.html); Parler needs natural-language descriptions generated with Data-Speech — [parler README](https://github.com/huggingface/parler-tts/blob/main/training/README.md); CSM uses `[speaker-id]` text prefixes — [Speechmatics](https://blog.speechmatics.com/sesame-finetune)
- Background music / noise: Emilia-Pipe = standardisation → source separation (Ultimate Vocal Remover) → diarisation → VAD → ASR → filtering; separation raised mean DNSMOS 2.52 → 2.88, filtering to 3.26; throughput 2.5 h raw/min on 8× RTX 4090 — [Emilia paper](https://arxiv.org/html/2407.05361v3); pipeline README — [Emilia-Pipe README](https://huggingface.co/spaces/slhlal/maskgct/blob/f7428c04a1c6a39c1ac353c9fc8ec763cee29f39/preprocessors/Emilia/README.md); Fish recommends `fap loudness-norm` — [v1.5.1 doc](https://raw.githubusercontent.com/fishaudio/fish-speech/v1.5.1/docs/en/finetune.md); Unsloth: "annotation quality and normalization matter more than tone or pitch"; avoid characters the tokenizer doesn't know — [Unsloth](https://unsloth.ai/docs/basics/text-to-speech-tts-fine-tuning); IndexTTS2 trainer filtered accented/mixed-language samples — [#501](https://github.com/index-tts/index-tts/issues/501)
- Overfitting signal: VoxCPM says ignoring input text can appear "within a few hundred steps on small datasets"; keep 1–3 epochs — [FAQ](https://voxcpm.readthedocs.io/en/latest/finetuning/faq.html); F5 Chinese run lost pronunciation clarity at later checkpoints — [#57](https://github.com/SWivid/F5-TTS/discussions/57); Fish S2-Pro LoRA produced near-silent output after 1000 steps — [#1346](https://github.com/fishaudio/fish-speech/issues/1346)

### Inferences
- 18–100 h of multi-speaker Turkish is enough for voice/style fine-tunes of Turkish-capable models (XTTS, Chatterbox-Multilingual, VoxCPM2 LoRA) and for F5-TTS-style character-level adaptation (Greek worked at 40 h), but it is 5–10× below what VoxCPM/IndexTTS2 maintainers consider adequate for teaching a language from scratch to an LLM-codec model; expect accent/intelligibility limits on Orpheus/Llasa/Qwen3 at 20 h, improving at 200 h.
- Required preprocessing stack (union of recipes): music/noise separation (UVR-MDX/Demucs class), resample per model (16 kHz Chatterbox/Llasa/VoxCPM2; 22.05 kHz XTTS/Piper; 24 kHz F5/Orpheus/CosyVoice/StyleTTS2), loudness normalisation, trim trailing silence, cap clips at 10–12 s for XTTS/CosyVoice2 and ≥ 3 s for VoxCPM, normalise text (numbers, abbreviations) and verify diacritics survive tokenization.
- Clustering-based speaker IDs matter only for models that consume them (Piper, StyleTTS2, CosyVoice utt2spk, CSM prefix, Fish speaker tags); prompt-conditioned models (F5, Chatterbox, VoxCPM, Orpheus LoRA) use reference audio instead, where same-speaker prompt/target pairing is what matters (IndexTTS2 thread found cross-utterance same-speaker pairing necessary to stop prompt bleed).

### Gaps
- No recipe quantifies acceptable residual background music or a DNSMOS threshold for fine-tuning (Emilia's thresholds are for pretraining corpus construction).
- No source compares Demucs vs UVR for TTS fine-tuning data; only UVR is named (Emilia).

## KQ6. Rough wall-clock on an RTX 5090 for a 20 h and a 200 h corpus, per model

### Takeaway
No RTX 5090 training timings exist for any TTS model; the only sourced timings are 4090 (F5), A100/H100 (Chatterbox, Qwen3), L40S (Llasa), T4 (Unsloth) and 4× A100 (StyleTTS2). Scaled by data volume only (not by GPU), the sourced points imply roughly: F5-TTS ≈ 0.5 day for ~60 h at 100k–150k steps (so ~hours for 20 h and ~1–2 days for 200 h on 4090-class hardware); Qwen3-TTS ≈ 1 h per 1.5 h × 8 epochs on an H100; Unsloth Orpheus LoRA ≈ 1–2 h per 3 h on a T4; everything else is unknown.

### Cited Findings
- F5-TTS: Greek 60 h → ~half a day on one 4090 for 100k–150k steps at 1,618 frames/batch; Spanish one epoch ≈ 6 h 51 min at 4,000 frames/batch (93k batches); 3090 setup for 60–80 h ran 10 epochs — [#57](https://github.com/SWivid/F5-TTS/discussions/57); German 4.2 M steps (GPU/time unknown) — [F5-TTS-German](https://huggingface.co/hvoss-techfak/F5-TTS-German)
- Qwen3-TTS: 1.5 h data × 8 epochs ≈ 1 h on one H100 — [Baseten](https://www.baseten.co/blog/fine-tuning-qwen3-tts-for-high-quality-voice-cloning/)
- Orpheus via Unsloth: ~3 h data, "a few epochs" ≈ 1–2 h on a Colab T4 — [Unsloth](https://unsloth.ai/docs/basics/text-to-speech-tts-fine-tuning); Turkish LoRA 20k samples × 8 epochs = 9,504 steps on A100s, time not stated — [AbDhumal](https://huggingface.co/AbDhumal/orpheus-3b-turkish-tts-v2)
- Llasa: 7,000 h ≈ 20 h on 4× L40S (plus separate xcodec2 preprocessing) — [MultiLlasa](https://huggingface.co/MultiLlasa/Llasa-1B-Multilingual-German)
- Chatterbox-Finnish: 16.6k samples, checkpoint step 986 on one A100 80 GB (time not stated) — [RASMUS](https://huggingface.co/RASMUS/Chatterbox-Finnish); Uzbek 12,500 steps (time not stated) — [Tohirju](https://huggingface.co/Tohirju/chatterbox-mtl-uzbek)
- StyleTTS2: 1 h fine-tune ≈ 4 h on 4× A100; 24 h from scratch ≈ 2.5 days on 4× A100 — [StyleTTS2](https://github.com/yl4579/StyleTTS2)
- Parler Mini: 45k h ≈ 1.5 days on 32× H100 — [parler README](https://github.com/huggingface/parler-tts/blob/main/training/README.md)
- XTTS Gradio fine-tune "can take up to 40 minutes" on Colab (dataset size unspecified) — [Coqui docs](https://coqui-tts.readthedocs.io/en/latest/models/xtts.html)
- VoxCPM example configs: 1,000 steps at batch 16 × 8,192 tokens (time not stated) — [VoxCPM guide](https://voxcpm.readthedocs.io/en/latest/finetuning/finetune.html)
- Preprocessing throughput: Emilia-Pipe 2.5 h raw audio per minute on 8× 4090 — [Emilia paper](https://arxiv.org/html/2407.05361v3); Orpheus SNAC preprocessing < 1 min per 1,000 rows — [Orpheus README](https://github.com/canopyai/Orpheus-TTS)
- RTX 5090 software note: `torch.compile` gives ~4× speedup on sm_120 per the field guide — [sm120 field guide](https://huggingface.co/datasets/witcheer/sm120-field-guide)

### Inferences
- Linear-in-data scaling of the sourced points (same epochs, 4090-class GPU) gives: F5-TTS ≈ 4 h (20 h corpus) / ≈ 1.5–2 days (200 h); Qwen3-TTS 1.7B SFT at 8 epochs ≈ 13 h (20 h) / ≈ 5.5 days (200 h) on H100 — likely too many epochs for 200 h, 1–3 epochs would be ~0.5–2 days; Orpheus LoRA ≈ 7–13 h (20 h) on a T4, i.e. a few hours on a 5090-class card, ~1–2 days for 200 h; Llasa ≈ 20 h × (200/7,000) × 4 GPUs ≈ 2–3 GPU-hours for 200 h at one epoch (likely dominated by xcodec2 preprocessing); Emilia-style cleaning of 200 h raw ≈ 10–11 GPU-hours on one 4090. All of these are my extrapolations, not measurements, and assume a 5090 is at least as fast as a 4090 (no sourced ratio).
- Preprocessing (separation + ASR alignment + codec extraction) is likely comparable to or larger than LoRA training time at 20 h scale.

### Gaps
- No RTX 5090 vs 4090/A100 training-throughput ratio for TTS workloads was found; no timing for XTTS GPT fine-tune, CosyVoice2 SFT, Chatterbox T3, VoxCPM, Fish, IndexTTS2 at a stated dataset size.

## KQ7. Turkish-specific adaptation reports

### Takeaway

## KQ8. RTX 5090 / Blackwell (sm_120) PyTorch and flash-attention compatibility

### Takeaway
PyTorch ≥ 2.7 with cu128 wheels officially supports Blackwell (sm_120) and Triton 3.3 compiles for it, and a Fish-Speech LoRA run on an RTX PRO 6000 Blackwell with torch 2.8.0+cu128 confirms training works; the open problem is FlashAttention: FA2 source builds for sm_120 crashed nvcc (issue open since Mar 2026), official wheels stop at torch 2.8, FA3 is unsupported, FA4 rejects sm_120 (no TMEM on GB202), so the practical path is PyTorch SDPA (cuDNN/flash backends) or community sm_120 builds.

### Cited Findings
- PyTorch 2.7 (Apr 2025) "introduces support for NVIDIA's new Blackwell GPU architecture and ships pre-built wheels for CUDA 12.8"; cuDNN/NCCL/CUTLASS upgraded; Triton 3.3 adds Blackwell support with torch.compile; install `torch==2.7.0 --index-url https://download.pytorch.org/whl/cu128` — [PyTorch 2.7 blog](https://pytorch.org/blog/pytorch-2-7/)
- Field guide: torch < 2.7 (cu124/cu126) ships no sm_120 kernels ("no kernel image is available"); use torch ≥ 2.7 cu128; torchaudio must match torch's CUDA ABI; claims CUDA 13.x miscompiles SOFT_MAX for sm_120 and CUDA 12.8 needs a glibc 2.41 header patch (unverified single-source claims); bitsandbytes 4-bit works; Triton bundles ptxas; use the `-open` driver variant; torch.compile ~4× on sm_120 — [sm120 field guide](https://huggingface.co/datasets/witcheer/sm120-field-guide)
- flash-attention #2361 (opened 2026-03-17, open, no maintainer reply): building FA2 with `FLASH_ATTN_CUDA_ARCHS=120` segfaults nvcc on backward kernels (CUDA 12.8/12.9, torch 2.9.1+cu128); v2.8.3 wheels only up to torch 2.8 (undefined symbol on 2.9); PyTorch SDPA with cuDNN flash reaches ~160 TFLOPS on a 5070 Ti; FA4 sm_120 tracked in #2307; Triton sm_120 PTX fix merged — [Dao-AILab #2361](https://github.com/Dao-AILab/flash-attention/issues/2361)
- FA4 on 5090: SM120 "uses an older instruction family and the TMEM hardware is absent from the GB202 die"; Python checks reject SM120; "FA2 via Triton remains the best available attention kernel for the RTX 5090" — [gist](https://gist.github.com/solatticus/aab6ec3a0436748b021cbbdd12e8c739)
- Community package bundling six upstream PRs for SM120/121 (RTX 5090, RTX PRO 6000, GB10), CUDA ≥ 12.8, installable via `kernels` — [flash-attn-4-sm120](https://huggingface.co/SecondNatureComputing/flash-attn-4-sm120); a Windows FA 2.8.3 wheel locked to CUDA 13 + torch 2.11 nightly — [tylerh216 wheel](https://huggingface.co/tylerh216/flash-attn-windows-5090)
- vLLM on a 5090 works with torch 2.9 cu128 and `VLLM_FLASH_ATTN_VERSION=2` ("FA3 is unsupported on Blackwell") — [vLLM forum](https://discuss.vllm.ai/t/vllm-on-rtx5090-working-gpu-setup-with-torch-2-9-0-cu128/1492)
- Evidence of TTS training on consumer Blackwell: Fish S2-Pro LoRA on RTX PRO 6000 Blackwell, torch 2.8.0+cu128, bf16 — [fish-speech #1346](https://github.com/fishaudio/fish-speech/issues/1346)
- Recipes that hard-require flash-attn: Orpheus README installs `flash_attn` — [Orpheus README](https://github.com/canopyai/Orpheus-TTS); Orpheus-Turkish used FlashAttention-2 on A100 — [AbDhumal](https://huggingface.co/AbDhumal/orpheus-3b-turkish-tts-v2); Qwen3-TTS inference example uses `flash_attention_2` — [Qwen3-TTS finetuning](https://github.com/QwenLM/Qwen3-TTS/blob/main/finetuning/README.md); Unsloth uses Flash Attention 2 — [Unsloth](https://unsloth.ai/docs/basics/text-to-speech-tts-fine-tuning); Chatterbox fine-tune may need `cfg._attn_implementation = "eager"` on newer transformers — [Uzbek card](https://huggingface.co/Tohirju/chatterbox-mtl-uzbek)

### Inferences
- On a 5090 use torch ≥ 2.7/2.8 cu128 and set `attn_implementation="sdpa"` (or eager) for HF-based trainers (Orpheus/Llasa/Qwen3/Chatterbox) unless a community sm_120 flash-attn build is verified; F5-TTS, VoxCPM, CosyVoice, XTTS, StyleTTS2 and Piper do not depend on flash-attn and should run with stock cu128 wheels.
- Unsloth's "Flash Attention 2" path and any `pip install flash_attn` in a recipe is the most likely install-time failure on Blackwell; budget time for this.

### Gaps
- No official Dao-AILab release note adding sm_120 wheels was found as of 2026-10-26; status of #2307 (FA4 sm_120) not fetched.
- No measured attention throughput (SDPA vs community FA) on a 5090 for TTS sequence lengths.
