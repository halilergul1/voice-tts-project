# VoxCPM2 Turkish LoRA, Stage 0/1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Audit the full-catalogue corpus for garbage, clean it (vocal separation, strict tier), produce VoxCPM2 training manifests, measure baselines, and train the Stage 1 "prosody" LoRA on the RTX 5090, with a checkpoint that beats Trendyol-TTS in a blind listen.

**Architecture:** Four small scripts in this repo (audit, separate, manifest, eval) plus one YAML config drive the upstream `VoxCPM` trainer unchanged. Pure decision logic (text flags, tier selection, reference pairing, source choice) lives in `ttsdata/` modules with unit tests and runs on the Mac against the 18 h local dataset; the GPU work (separation, UTMOS scoring, training, synthesis) runs on astrobot after the catalogue job drops `data/logs/pipeline_done`.

**Tech Stack:** Python 3.12, `voxcpm` (pip, Apache-2.0, `openbmb/VoxCPM2`), `audio-separator` (BS-Roformer vocals), `utmosv2` (git, MIT), faster-whisper large-v3-turbo (already on astrobot), pyloudnorm, soundfile, numpy, pytest.

**Spec:** `reports/Turkish expressive TTS model options.md` (sections "Data preparation", "Training stages", "Evaluation protocol"); upstream facts from the VoxCPM fine-tuning guide and FAQ (voxcpm.readthedocs.io, fetched 2026-10-26).

## Read this first (human overview)

Order of operations once the catalogue job finishes on astrobot:

1. **Audit** (Task 1): one script, one markdown report, one `quality.jsonl` with per-clip metrics, one `listen/` folder. You listen to ~60 clips before any training. Nothing proceeds if the audit lists problems.
2. **Separate** (Task 2): strip background music from clips that have it, keep the originals for the rest, re-normalise loudness. Adds a `music_db` column to the audit.
3. **Manifest** (Task 3): pick the strict tier (CER ≤ 0.05, 3–20 s, low music, speaker cluster ≥ 10, no text flags), pair 40 % of rows with a same-speaker reference clip, mix in 15 % FLEURS-tr as replay, write VoxCPM JSONL.
4. **Baselines** (Task 4 + 5): install VoxCPM2 in its own venv, synthesise the Freya-TR-Eval sentences with VoxCPM2 zero-shot and Trendyol-TTS, score them. Numbers must roughly match the published ones or the harness is wrong.
5. **Stage 1 LoRA** (Task 6): rank-64 LoRA on LM + DiT, lr 1e-4, batch 16, 1 epoch on a 60 h slice first, checkpoints every 250 steps, each scored by Task 4. Blind A/B of 20 sentences against Trendyol-TTS decides.

Everything in Tasks 1–4 is code that can be written and unit-tested now on the Mac; only the full-size runs wait for the server. The 18 h local `data/dataset/` is the dev fixture.

- VoxCPM data rules (fine-tuning guide): clips 3–30 s, < 1 s unstable; trailing silence < 0.5 s; transcript must match audio exactly; remove noisy samples; 30–50 % of rows carry `ref_audio` from the same speaker; `ref_audio` must not be the target clip; `dataset_id` integer, default 0.

Expected VRAM ≈ 20 GB.
- Checkpoint dirs are `step_XXXXXXX/` under `save_path` with a `latest` symlink; a LoRA checkpoint must contain `lora_weights.safetensors` + `lora_config.json`. Inference: `VoxCPM.from_pretrained("openbmb/VoxCPM2", lora_weights_path=<step dir>)`; inference LoRA settings (`r`, `alpha`, `enable_lm`, `enable_dit`) must match training.
- Text fed to VoxCPM = `normalized_text` (digits already expanded by num2words). No style prefix in Stage 1. Instructions, when used later, are written in Turkish, in parentheses, at the start of the text.
- Clip sample rate stays 24 kHz on disk (VoxCPM resamples to 16 kHz itself). Loudness −20 LUFS, peak ≤ 0.99 (existing build values).
- Paths in a manifest are relative to the manifest's directory.
- This folder is not a git repository: skip the commit steps, keep the task order.

## Review Focus

- **Short clips (1–3 s) are the majority of the corpus** (median 2.7 s). VoxCPM wants 3–30 s. Tier A excludes < 3 s; the audit must report the hours lost so the 1–3 s tier is a conscious Stage 3 decision, not an accident. Test: `select_tier` drops a 2.9 s row and keeps a 3.0 s row.
- **Text that will be read wrong**: leftover digits, abbreviations (`Dr.`, `TBMM`, `vs.`), all-caps acronyms, bracket/parenthesis leftovers, `♪`, English words. Test: `text_flags` returns the right flag for each; tier excludes any flagged row.
- **Reference pairing with the wrong voice**: impure small clusters. Pairing only inside clusters with ≥ 10 clips, never the same clip, prefers a clip with the same `speaker_hint` when the target has one. Test: pairing never returns the target id or a different cluster.
- **Music under dialogue**: separated audio can sound hollow when there was no music. The source choice uses the instrumental-to-vocal loudness gap, with a tested threshold. Test: `choose_source` returns `original` at −12 dB and `separated` at −8 dB (the separator leaves a −12..−25 dB residue on clean read speech), and `original` whenever the stems are unreliable (instrumental above the voice, or the vocal stem under 25 % of the original's RMS).
- **Manifest path and field mistakes** silently break training (relative paths, `ref_duration` missing when `ref_audio` present, trailing silence). Test: every manifest row validates against a schema function before writing.

- [ ] **Step 3: Implement `ttsdata/quality.py`**

`text_flags`: regexes over `normalized_text`: `digits` = `\d`; `abbrev` = a token of 1–4 letters ending in `.` that is not sentence-final, plus the list `vs., vb., dr., prof., av., bkz., no., tel.`; `allcaps` = a token of ≥ 2 uppercase Turkish letters; `leftover` = any of `( ) [ ] ♪ * #` or a `<...>` tag; `fragment` = text starts or ends with `...`; `latin` = a word whose letters include `w, x, q` or an English stop-word list (`the, and, you, with, what`). Return the sorted unique flag list.
`silence_edges`: frame RMS (20 ms hop), first/last frame above `thresh_db` relative to full scale; return seconds before/after.
`episode_outliers`: per uid mean `cer`; flag uids whose mean is above the median of uid means + 2·MAD, return `[{"uid", "mean_cer", "n"}]` sorted worst first.
